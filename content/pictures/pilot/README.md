# Три сюжетные мозаики — пилот

Цель нового старта — **2500 уникальных композиций для 2500 уровней, каждая используется один раз**.
Пилот содержит **3 из 2500**, а не три шаблона для размножения. Другой размер, зеркало, перекраска
и новая сложность той же картинки не считаются новым рисунком. Daily остаётся отдельно.

| Композиция | Поле | Цветов | Тестовая задача | Seed |
|---|---|---|---|---|
| Маяк внутри груши | 14×16 | 6 | 501 | 3 |
| Остров в чемодане | 18×22 | 6 | 551 | 3 |
| Чайная на спине улитки | 22×28 | 6 | 601 | 2 |

Номера 501/551/601 — изолированные тестовые места для диапазона доступных вариантов,
**не назначение новых рисунков в основной каталог**. Здесь нет изменения игровых L501/551/601.
Дистанция между примерами позволяет проверять их вместе без искусственных конфликтов соседних задач.
Решатель проверяет победную последовательность, возможность проиграть, подсчёт клеток/подов и сложность.

## Файлы

- `references/story-concepts-v1.png` — исходный лист идей, созданный через image generation. Это концепт,
  не готовые игровые сетки: на нём больше оттенков и деталей, чем в игре.
- `src/*.grid.txt` — отдельные вручную составленные сетки точного целевого размера, строки сверху вниз.
  Ни одна из трёх сеток не получена масштабированием другой.
- `src/*.meta.json` — роли, группы цветов, происхождение и легенда для существующего импортера.
- `lib/*.json` — результат штатного `pictures import`: строки снизу вверх, вычисленная структура.
- `samples/levels/` и `samples/validation/` — примеры задач, собранные существующим генератором и проверенные
  решателем. Mapping и mirror не редактировались после решения.
- `compositions.json` — постоянные ID композиций, палитры пилота, номера и seed воспроизводимых примеров.

Импортер ставит `review.status=approved` после формальных проверок — это его существующее поведение.
**Художественный статус пилота остаётся `pilot-awaiting-owner-review`** в реестре. Он не означает, что владелец
уже утвердил эти картинки. Данные намеренно находятся вне `content/pictures/lib` и `content/catalog`;
стандартная сборка игры и APK их не включают.

В чемодане подкладка тёмно-фиолетовая: так задача сохраняет шесть различимых игровых цветов и четыре семейства.
Тонкие детали концепта упрощены до клетки. Палитры проверяются отдельно от проходимости: обычный генератор
может менять оттенки внутри группы и объединять роли. Пилот фиксирует доступные варианты, запрещает слияние
и использует найденные seed, при которых выбранная палитра сохраняется. Это ещё не универсальный механизм
фиксации художественной палитры для будущих 2500 сцен.

## Воспроизведение на своём компьютере

Нужны Git, .NET 10 SDK и PowerShell (проверено на PowerShell 7). AI, GPU, сервис генерации изображений
и Android SDK для генерации задач не нужны. Все рисунки уже лежат в репозитории.
Из корня checkout:

```powershell
./tools/catalog/build-art-pilot.ps1 -Render
```

На Linux/macOS:

```sh
pwsh -NoProfile -File tools/catalog/build-art-pilot.ps1 -Render
```

Скрипт собирает только CLI и настольный renderer, импортирует рисунки в `content/work/art-pilot-local/`,
генерирует три задачи, проверяет палитры, выполняет `validate`, `score`, `review` и сверяет определения
с сохранёнными примерами. Опция `-Render` дополнительно создаёт лист настоящего игрового борда
`content/work/art-pilot-local/game-render/mosaic-pilot.png`. Без неё доступны диагностические PNG и
`review/index.html` от pipeline. Production-каталог и исходники рисунков не перезаписываются; APK не собирается.
Повторный запуск использует те же seed и должен дать те же определения.

Для рендера сохранённых примеров без новой генерации:

```sh
dotnet run --project playtest/preview -c Release -- --mosaic-pilot --out content/work/art-pilot-render
```

Это вызов настоящего `BoardPainter.Draw`, с актуальными объёмными клетками геймплея.
PNG — обзор художественного пилота, а не снимок всей страницы игры. Renderer не меняет каталоги сборки.

## Проверка уникальности

Дополнительная проверка требует только Python 3, без сторонних пакетов:

```sh
python tools/catalog/check-compositions.py --catalog content/pictures/pilot/samples
python tools/catalog/test_compositions.py
```

Проверяются повторные ID, соответствие реестра JSON-картинкам, повтор композиции между задачами и
одинаковые клеточные структуры независимо от цветов, зеркала, поворота и простого nearest-масштабирования.
Проверка консервативна; она не может определить, что два разных рисунка рассказывают одну историю.
Уникальность идеи проверяется визуально. Техническим вариантам одной сцены нельзя выдавать новые ID композиций.

Для будущего полного каталога:

```sh
python tools/catalog/check-compositions.py --registry <registry.json> --lib <new-library> --catalog <new-catalog> --complete
```

`--complete` требует 2500 визуально утверждённых композиций, полный диапазон L1–2500 и ровно одно использование
каждой композиции. **Для этого пилота он должен завершаться с ошибкой**: здесь пока только три рисунка.
Команда пока является отдельной проверкой нового художественного каталога, не автоматическим этапом старых
`build-catalog`/`publish`. Текущие игровые определения сохраняют старые правила повторов. Полный переход
и подключение строгой проверки к публикации выполняются при подготовке новой библиотеки, не подменяются
переименованием старых вариантов.
