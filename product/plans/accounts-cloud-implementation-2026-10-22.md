# Аккаунты и сейвы: подготовленная основа

Дата: 2026-10-22. Решение: [UGS + PGS, перенос между платформами позже](accounts-cloud-decision-2026-10-22.md).

## Что реализовано без кабинетов

- Сейв имеет неизменяемого при обычной игре владельца `cloudOwnerId`. Имя и локальный ID устройства не используются как облачная идентичность.
- `AccountProfiles` хранит владельцев в отдельных каталогах, выбирает активный профиль после перезапуска, сохраняет старый гостевой файл и переносит ранее привязанный профиль при загрузке. Старая ссылка на SaveService аккаунта A не пишет файл B. При повреждении обеих копий существующий профиль не заменяется пустым.
- Первая привязка гостя фиксируется на диске до отправки. Даже потерянный ответ не позволяет передать того же гостя аккаунту B автоматически.
- Занятая PGS/Apple-привязка больше не вызывает скрытый SignOut и вход в чужой аккаунт. Адаптер возвращает отдельный результат ExistingAccount.
- `AccountRestoreService`: подготовка восстановления → информация о целевом аккаунте → явное подтверждение. Изменение локального прогресса, отмена или смена платформенной сессии аннулируют подготовленное подтверждение. Новая идентичность получает пустой профиль, существующая — свой сейв. Ветка локальных данных перед заменой архивируется.
- `CloudSaveSync` использует владельца, поколение сессии, сохранённый отпечаток последнего подтверждённого состояния и условную запись по версии облачного документа. Офлайн-очередь — это сохранённое локальное состояние и его общий предок, поэтому она переживает перезапуск.
- Если поменялась только одна сторона, отправляется локальный либо восстанавливается целый удалённый снимок. Если изменились обе — Conflict, обе ветки остаются для разрешения. Нет автоматического выбора по уровню/часам устройства.
- Кошелёк, бусты, покупки, вещи и отметки получения наград переносятся вместе. Старое объединение SaveMerge запрещено для привязанных профилей и больше не используется CloudSaveSync. Это устраняет сценарий «новая вещь + баланс до её покупки».
- Покупка во время отправки не теряется: подтверждается отправленный снимок, новые изменения остаются в очереди. После потерянного подтверждения повторное чтение узнаёт уже записанное состояние без повторного начисления.
- Награда за уровень имеет постоянную отметку получения; повторный callback не платит ещё раз. Это дополнительная защита к проверке нового уровня в progression, не серверная проверка прохождения.
- Unity Boot использует репозиторий профилей; Settings показывает состояние облака/конфликта/ошибки привязки. LeaderboardClient в Boot не отправляет прогресс владельца A, если авторизация сейчас принадлежит B, и очищает чужую кэшированную позицию при обновлении.

## Важная граница этого этапа

Это **не готовый запуск онлайн-аккаунтов**. .NET-проверка компилирует общий клиент с Unity-заглушками; условно включаемые UGS SDK-адаптеры требуют отдельной сборки с настоящими пакетами. Android playtest остаётся локальным, APK не собирался.

[Игровой интерфейс аккаунта](account-in-game-ux-2026-10-22.md) добавлен в Android playtest и Unity; восстановление текущего аутентифицированного владельца подключено в Unity. Полное переключение на другого владельца через AccountRestoreService пока не выведено готовой кнопкой. Перед таким переключением хост должен завершать/отменять запросы предыдущего профиля и пересоздавать все зависящие от игрока сервисы после Applied; нельзя просто подменить сейв под старым GameFlow, daily, покупками и UI. Платформенный вход в существующий аккаунт должен быть отдельным явным действием, не побочным эффектом Link.

Сейчас UGS-адаптер обновляет только существующий документ с write lock. Он **не создаёт** новый через незащищённый SaveAsync: отсутствие lock в Unity не даёт гарантии create-if-absent. Для нового документа возвращается NeedsInitialization. Перед live-включением нужен серверный bootstrap с проверенной защитой от одновременного создания; старые облачные документы без владельца также требуют явной миграции. Модель атомарного создания проверена на тестовом провайдере, не на UGS.

Снимки защищают от случайного смешивания кошельков, но не заменяют авторитетную серверную экономику. Серверные операции наград/трат, проверка чеков и доказательств прохождения, ограничения клиентской записи и безопасное разрешение двух расходящихся финансовых веток остаются отдельной частью перед запуском покупок. Пока конфликт не решён, не пытаемся «угадывать» баланс и не предлагаем загрузить любой более выгодный сейв поверх сервера.

## Контракт провайдера

`IAccountCloudSaveService`:

- PlayerId — фактический аутентифицированный UGS-владелец; SessionVersion меняется при смене/потере сессии, даже A → B → A.
- LoadFor/StoreFor проверяют ожидаемые owner/session до запроса; ответ прежней сессии нельзя применять к новой.
- WriteLock — непрозрачная версия именно прочитанного документа. StoreFor выполняет атомарное сравнение и запись; null означает атомарное создание только у провайдера, который умеет гарантировать отсутствие записи. Иначе NeedsInitialization.
- Права на сервере определяются токеном, а не переданным клиентом ID. Поле владельца внутри JSON — проверка согласованности, не средство авторизации.
- Повтор после ошибки сначала читает состояние, не слепо повторяет запись.

## Проверка без внешних сервисов

В этой среде .NET находится в `/workspace/.dotnet`, CLI home — `/workspace/.dotnet-home`. Пример запуска:

```bash
DOTNET_CLI_HOME=/workspace/.dotnet-home /workspace/.dotnet/dotnet test client/DotnetCheck/Bloomlings.Client.DotnetCheck.csproj --no-restore --filter 'FullyQualifiedName~AccountCloudSyncTests|FullyQualifiedName~SaveServiceTests|FullyQualifiedName~SaveMergeTests|FullyQualifiedName~EconomyServiceTests|FullyQualifiedName~PurchaseLedgerTests|FullyQualifiedName~CloudSaveAndLeaderboardTests|FullyQualifiedName~Wardrobe|FullyQualifiedName~ProfileServiceTests|FullyQualifiedName~Localization'
```

Тесты включают два отдельных локальных сейва с общим условным сервером, одновременные записи, потерянный ответ, изменение сейва во время запроса, смену владельца и возврат A → B → A, восстановление после перезапуска, отмену подтверждения, сохранение прежнего профиля и повреждённые файлы. Это доказательство логики, не проверка живого UGS, PGS или настоящих транзакций магазина.

## Клиентский кэш и очередь

Подготовлен [клиентский компонент](../../client/Assets/Bloomlings/Services/Economy/Online/README.md): встроенный и
сохранённый каталог для офлайн-просмотра, подтверждённое владение и переодевание, неизменяемые запросы и отдельные
доказательства офлайн-прохождений. Покупку можно начать после онлайн-чтения и подтверждения цены. Неотправленная
покупка после перезапуска ждёт нового подтверждения; отправленная с неизвестным исходом повторяется тем же запросом.
Снимок кошелька и удаление подтверждённой операции записываются вместе. Смена аккаунта, повреждение файлов и
обновление каталога не сбрасывают номера запросов и не превращают локальную награду в серверную валюту.

Это ещё не переключение текущего APK на серверную экономику: подготовленный UGS-транспорт не регистрируется
автоматически, а боевой хост/все UI-пути трат и наград требуют согласованного подключения после настройки сервисов.
