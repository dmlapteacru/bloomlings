# Единая экономика и подготовка рейтинга

Дата: 2026-10-23. Продолжение [нативных покупок UGS](native-ugs-purchases-2026-10-23.md). **Live-сервисы не включены; обычный APK остаётся локальным dev-клиентом. APK не собирался.**

## Сделано в игровом клиенте

`DesignApp` может явно получить `OnlineEconomyClient` и создать единый `ServerEconomy`. Подмена части callback магазина не включает серверный режим. В этом режиме цены берутся из кэшированного серверного каталога, кошелёк/заряды/владение/платные награды — из подтверждённого снимка. Локальные `Grant`, `TrySpend`, покупки, выдачи milestones, daily, IAP ledger и миграция старых пробных предметов не добавляют ценности. Tester +/- петали, skip/back и reset не дают обойти режим.

Первое включение требует одновременно явного `activateServerEconomy:true` от хоста, уже проверенного provisioned-снимка текущей сессии и совпадающего прогресса после согласованной миграции. Это технический gate, **не реализация миграции или доказательство её корректности**. Нельзя передать игроку эту кнопку. Уже переведённый профиль открывается офлайн с durable cache, но не с локальным кошельком.

`serverEconomyOwnerId` сохраняется в PlayerSave. Отдельный fsync-файл `save/server-economy-owner` создаётся раньше записи снимка: откат к старому backup или порча двух сейвов не возвращает аккаунт в локальный режим. В этом случае загрузка останавливается, сохраняя основной/резервный файл; recovery UI и загрузка профиля из сервера ещё нужны. Legacy whole-save sync/restore не переносит серверный кошелёк. Внешний host обязан закрывать корутины/адаптер при смене аккаунта (`DesignApp.Dispose`) и перестраивать весь граф профиля.

В Account & progress есть Pending purchase. Открытие этой карточки само по себе не повторяет оплату: игрок выбирает Check purchase либо Cancel request. Закрытие карточки оставляет запрос в durable outbox. Если отмена не получила ответ, её точный запрос сохраняется и проверяется после перезапуска.

## Что значит отмена

`cancel_purchase` использует **тот же installationId + sequence**, что исходная покупка, и несёт её точную строку `purchaseJson`. Сервер одной CAS-записью фиксирует либо покупку, либо tombstone отмены:

- отмена победила — нет списания; поздняя исходная покупка возвращает «отменено»;
- покупка победила — отмена возвращает исходный результат покупки; автоматического возврата или ложного сообщения об отмене нет;
- потерян ответ — точный повтор возвращает прежний исход;
- курсор не отматывается, запись очереди не удаляется без ACK.

Отменять можно только платные виды операций; награду, обычное использование имеющегося бустера, другой sequence/владельца и вложенную отмену нельзя. После изменения цены сохраняются прежние варианты для запроса исходной квитанции. Проверка/отмена покупки останавливается на её sequence, чтобы следующая награда в очереди не затёрла результат окна.

Daily/ad операции содержат день, полученный при online-read сервера. Вчерашний запрос не получает сегодняшнюю бесплатную награду. Локальные часы и ad stub не создают серверное разрешение.

## Офлайн-победы и миграция гостя

`WinEvidence` хранит версию, ID попытки, SHA-256 определения/картинки, принятые команды и конечный state hash. Preflight `ValidateAndReplay` воспроизводит команды на **доверенных** definition/picture/options, проверяет победу и считает фактические бустеры. Ограничения: 1 МиБ, 20 000 команд. Это не подпись, не античит и не разрешение награды: пользователь может изготовить корректное решение; право на платные бустеры и допустимость попытки должен проверять сервер.

В нативном игровом пути evidence записывается **до** продвижения на следующий уровень. Для гостя `save/guest-wins/level-xxxxx.json` — первая победа, checksum, запись через temp+fsync+move без перезаписи. Нужен для будущей миграции, не загружается в кошелёк автоматически. В серверном режиме evidence уходит в owner-scoped журнал reward intents, а экран победы показывает ожидание проверки. Деньги до подтверждения не выдаются.

Старые гостевые победы не получают доказательства задним числом. Ни wallet, ни список купленных предметов из гостевого сейва нельзя объявлять серверными данными. Перед реальной миграцией нужно выбрать политику для старого прогресса, архивировать гостевую ветку, привязать её единственному новому владельцу и провести атомарный bootstrap. Занятый PGS-аккаунт означает отдельное явное восстановление, а не клонирование текущего прогресса.

## Рейтинг

[Отдельный план и формула](leaderboard-strategy-2026-10-23.md): общий прогресс плюс предложение недели, лучшие пять дней, равная помощь, 150/125/100, общие места. `CompetitionRules` проверяет расчёт без подключения. В игре кнопка Ranking rules открывает карточку в существующем UX. Недельный режим/отправка/награды выключены; нет вымышленных соперников и мест. Существующий `SubmitProgress` с одним хешем не является проверяющим сервисом.

## Перед live-включением

1. Нативная PGS → UGS Authentication, UGS project/environment, owner-scoped профили, token refresh и явный account switch. Unity SDK сам по себе не подключает .NET APK.
2. Атомарный bootstrap + утверждённая миграция; восстановление повреждённого server-профиля с UI, не падение приложения.
3. Trusted replay issuer с закреплённым контентом, разрешениями попытки и учётом бустеров. Привязать обычные/ежедневные выигрыши к ticket; отдельно согласовать бесплатные tutorial uses (preflight считает фактическое использование без доверия к клиентскому demo count).
4. Завершить связь платного buy-and-use с durable игровой попыткой. Сейчас ACK применяет команду только в ещё живом игровом окне: уход/закрытие приложения после серверного расхода требует согласованной политики восстановления. Нельзя включать live-расход, пока это не решено.
5. IAP billing и rewarded SSV: серверные выдачи атомарно, никаких local ad stub / receipt fallback.
6. Отдельное безопасное облачное хранение **неэкономического** прогресса/настроек и разрешение конфликтов. Проверка кошелька не сообщает, будто весь прогресс уже сохранён в облаке.
7. Утвердить недельные правила; реализовать изолированную игровую попытку, trusted приём и серверную таблицу. C# расчёт не заменяет серверный endpoint.
8. Проверки на реальном Android: airplane mode, kill после отправки/ACK, смена аккаунта, reinstall/recovery, два устройства, старый/повреждённый кэш. Android workload и live credentials в этой среде отсутствуют.

## Проверка этого изменения

- **210 клиентских тестов**: покупки, ACK/повторы/отмена, reservation до ACK, смена сессии, цены, marker/recovery, replay/архив, расчёт рейтинга, legacy cloud guards, профиль/гардероб/daily/ledger.
- **51 backend-тест**, включая гонку отмены и покупки, неизменяемые квитанции и просроченный день; генератор deployment соответствует исходникам.
- **18 финальных игровых PNG** (win, milestone, правила, Account/pending/cancelled), три формы телефона: `checks: OK`. Карточки проверены визуально. Реальные нажатия ведут Account → pending → отмена; проигранный/неопределённый ответ не рисует успех.
- Native meta/animator check: **172 прогона, 0 ошибок**, 84 уровня с быстрыми тапами, `ALL OK`. Реальный L12 сохраняет evidence и воспроизводится по нему на доверенном контенте.
- Независимые ревью Astra по отмене и единому серверному режиму: найденные проблемы исправлены; оставшихся блокеров в подготовленном контуре не выявлено. Это не проверка live UGS, SDK или Android-устройства.
