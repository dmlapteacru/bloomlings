# Аккаунт и облачный прогресс: игровой интерфейс

Дата: 2026-10-22. По решению владельца интерфейс реализован **в игре**, без HTML-прототипа.

## Где открыть

Текущий Android playtest: **Settings → Account & progress**. Экран использует существующий Kit: деревянная рамка, кремовая поверхность, зелёная основная кнопка, крупные области нажатия. Обратный переход сохраняет настройки под окном. Тот же сценарий добавлен в Unity Home → Settings; общее состояние находится в `UI/Design/AccountPanel.cs`.

В текущем .NET APK нет настроенных аккаунтов: показываются действительные локальные имя, уровень, петали и «Saved on this device». Вход недоступен; нет тестового логина, фальшивой синхронизации или переключателей симуляции в игре. PNG-рендерер отдельно проверяет остальные состояния с тестовым провайдером, который не попадает в APK.

## Сценарии

- Локальный профиль: краткое объяснение хранения прогресса; платформенная кнопка появляется только при доступном провайдере.
- Подключённый профиль: ручная синхронизация, состояние облачной копии или ожидания сети.
- Ошибка: возможность повторить без очистки локального профиля.
- Конфликт: отдельная кнопка Review cloud save; ни максимальный уровень, ни более высокий баланс не выбирают ветку автоматически.
- Подготовка восстановления ничего не меняет. Два отдельных блока показывают имя, уровень и петали устройства и облака. Действия: Use cloud save / Keep device save. Второе только закрывает сравнение, не перезаписывает облако.
- Подтверждение действительно пять минут. Изменение локального сейва, платформенной сессии или облачной версии требует нового сравнения. Повторный тап не отправляет второе восстановление. Закрытое окно не открывает старое сравнение после запоздавшего ответа.
- При восстановлении сохраняется отдельная файловая копия текущей ветки `save/conflicts/<id>/player_save_v1.json`; только после успешной записи заменяется активный снимок. Петали/предметы заменяются вместе, не объединяются.

## Подключение сервисов и границы

`IAccountPanelGateway` передаёт факты/доступные действия и выполняет операции. Общий UI не пишет кошелёк и не переключает владельцев.

`CloudAccountPanelGateway` подключён к **Unity** auth/cloud/sync через Boot/HomeController. Он умеет привязку, синхронизацию и явное восстановление облака **текущего аутентифицированного владельца** — как для его локального профиля, так и для ещё непривязанного гостя. Перед заменой повторно читает облако и проверяет обе ветки. Объект PlayerSave сохраняется, чтобы сервисы читали тот же экземпляр; производная прогрессия и Home обновляются.

Занятая PGS/Apple-привязка показывает сообщение, не вызывает SignOut и не переносит текущий прогресс. **Вход в другой существующий платформенный аккаунт и переключение всего графа сервисов пока не выведены как готовая операция.** Их нельзя включать одним изменением токена; используется отдельный протокол AccountProfiles/AccountRestoreService.

**Это не включение live UGS/PGS.** Реальные SDK-пакеты, OAuth/сертификаты, безопасный bootstrap облачного документа и тестирование на устройстве ещё нужны. В текущем Android APK используется локальный gateway. Вопрос единого релизного хоста (.NET Android или Unity) остаётся до SDK-подключения: ввод настроек Unity сам по себе не подключит .NET APK.

Серверная экономика также не включается частично. Экран аккаунта не переключает магазин/награды на смешанный локальный и серверный кошелёк. Существующая покупная карточка остаётся; отдельная привязка её состояний pending/reprice к OnlineEconomyClient вместе с миграцией всех наград и трат остаётся перед live-включением. Схема покупки без сети и точного повтора после потерянного ответа реализована и проверяется в OnlineEconomyClient, а не имитируется этим UI.

## Проверка

- AccountPanelTests: одиночный dispatch, поздние ответы, A→B→A, отмена сравнения, локальная игра во время загрузки, изменение облачной ветки, архив до замены, непривязанный гость, запрет восстановления чужого владельца, успешная первичная привязка, истечение подтверждения.
- Регрессия: AccountCloudSyncTests, OnlineEconomyClientTests, PurchaseConfirmTests, SaveServiceTests, Wardrobe. Вместе с AccountPanelTests: **119 passed, 0 failed, 0 skipped**.
- Игровые PNG-кадры 240–247: Settings, локальный профиль, ожидание сети, конфликт, сравнение, облачная копия, недоступный сервис, ошибка. Три формы телефона: 16:9, 19.5:9, 21:9; все 24 PNG и проверки прошли (`checks: OK`). Проверяются safe area, размеры/перекрытия целей и локализованный заголовок; переход Settings → Account проверяется реальным нажатием по игровому hit target.
- Проверка Unity выполняется вне редактора с API-заглушками; реальные SDK и Android-устройство этим не проверены. APK по просьбе владельца не собирался.
