# Результаты первого ручного теста L1–30

19 октября 2026. Один участник — владелец, знакомый с жанром и Colony Flow. [Исходный экспорт](results.json) сохранён без изменений; [пересчёт](review.json) получен повтором каждой принятой команды на точной версии правил и каталога. [Визуальный разбор](index.html) показывает занятость мест и поле по шагам. [Предложение следующего теста](../../plans/gameplay-pilot-v2-plan.md).

## Результат

Пилот не подтвердил интерес и сложность. По устному отзыву почти везде хватало выбирать видимый цвет, не думая о столбце. Пять мест редко ощущались ограничением. Мостик понравился как идея, но реализация слаба. L26 был единственным заметно интересным уровнем.

| Измерение | Результат |
|---|---:|
| Попытки | 32: 30 побед, 1 проигрыш, 1 ручной сброс L1 |
| Оценка сложности победных уровней | 29 «легко», 1 «хорошо» (L26), 0 «трудно» |
| Узнаваемость | 15 «да», 15 «не очень» |
| Медиана записанного активного времени победы | 14,879 секунды |
| Победные уровни с максимум двумя ожидающими командами | 23 из 30 |
| Решения при четырёх занятых местах в победных попытках | 1 из 432 действий, на L22 |
| Hard L16 / L23 / L29: максимум занятых мест после очистки | 3 / 2 / 3 |
| Hard L16 / L23 / L29: оценка и узнаваемость | Все «легко» и «не очень» |

Занятость измерена **после автоматической очистки**. Краткое выделение слота капсуле, которая тут же заканчивается, не считается длительным давлением. Решения со свободным последним местом считаются по состоянию перед принятым действием. Время — поле `elapsedMs` HTML, не отдельная мера раздумья и не время будущих мобильных анимаций.

Не узнались L3, L6–11, L13–16, L23, L28–30. В частности, большие L28 и L30 уже имели 26×28: одного повышения разрешения недостаточно. Замкнутые рамки для усложнения испортили часть силуэтов; сюжет и зависимость цветов нужно проектировать совместно.

## Что произошло на L26

Единственный проигрыш — попытка 27. После 12-го действия ожидали четыре капсулы: голубые с остатками 61 и 27, коричневая 29 и тёмная 12. Оставалось одно место.

На 13-м действии были открыты три варианта:

| Капсула | Результат очистки | Занято мест после действия | Продолжение |
|---|---:|---:|---|
| Голубая 22 | 0 клеток | 5 | Проигрыш |
| Коричневая 23, выбрана в попытке | 0 клеток | 5 | Проигрыш |
| Кремовая 25 | 154 клетки вместе с уже ожидающими командами | 0 | Есть выигрышное продолжение |

До этого действия после каждого фактического префикса сохранялась победа. Перебор не нашёл более ранней необратимой ошибки; лимит ни на одной из этих проверок не исчерпан. Второй заход завершился победой и оценкой «хорошо». Успешный путь при этом занял максимум три места: не нужно искусственно заставлять любое решение доходить до пяти.

Здесь появился полезный эффект: конкретная команда завершает целую цепочку, а слот до её входа имеет цену. Но ошибка «поставить недоступный цвет в последнее место» сама по себе ещё не делает задачу Hard. В новом варианте нужен более ранний выбор резерва и разумные альтернативы, а не только последний спасительный цвет.

## Почему проверка ботами не предсказала результат

Прежний генератор пропускал Hard по низкой доле случайных побед, слабой оценке ближайшей цветной границы и двум ошибочным ветвям. Это доказывало возможность проиграть, но не необходимость интересного планирования. Часть точек стояла рядом; ошибочный альтернативный тап мог быть явно бесполезен.

Добавлен диагностический набор простых стратегий без поиска будущих ходов. Правило **«бери самую большую доступную капсулу цвета, который сейчас доступен; равенство — левый столбец; готовый мостик строй слева»** прошло 29 из 30 уровней. Не прошёл только L16. Правило «первый слева подходящий цвет» отдельно прошло L16 и L23. Эти результаты не означают, что участник следовал таким алгоритмам; они показывают слабость критериев отбора партии.

Случайные стратегии проверены по 64 детерминированным попыткам на уровень, две стратегии с фиксированным выбором — по одному точному повтору. Описание каждой политики, результаты и исходные метрики сохранены в `review.json`. Доли ботов не являются оценкой человеческой вероятности победы.

## Почему выбор мостика оказался слабым

Проверены фактические состояния перед мостиком на L28, L29 и L30. На каждом доступны оба мостика. Если заменить выбранный правый на левый и **не менять ни один последующий тап пользователя**, победа сохраняется. Для обоих вариантов также найдено выигрышное продолжение.

Это не утверждение, что оба маршрута равнозначны во всех возможных состояниях. Но в этих трёх сыгранных случаях выбор переправы не потребовал менять очередь действий. Проверка «без мостика не пройти» была недостаточной: обязательное действие не равно содержательной развилке.

## Вывод для следующего теста

Цветные клетки с L1, герой знакомит со своим цветом на капсуле. Рабочий старт 16×18 вместо 11×12; силуэты перерисовываются, а не просто масштабируются. Скрытая капсула примерно L6, пара L10, содержательный Hard около L15, затем мостик с разными последствиями маршрутов. Меньше механик в одном показе, больше практики резерва и очереди.

Полная спецификация и границы эксперимента — в [новом предложении](../../plans/gameplay-pilot-v2-plan.md). Прежний игровой HTML и результаты сохраняются как v1; по этому разбору новый пилот ещё не публиковался.

## Воспроизведение

```bash
node tools/gameplay-pilot/review.mjs --results=product/playtests/pilot-v1-owner-2026-10-19/results.json --out=/tmp/bloomlings-owner-review
python3 tools/gameplay-pilot/build-review.py
```

Скрипт проверяет hash каталога и правил, исходы всех 32 повторов, точный учёт работы и допустимость команд. `null` результата поиска означает Unknown. Один опытный тестер достаточен для отрицательного продуктового вывода об этом пилоте, но не для статистики всей аудитории, удержания и монетизации. Производственные уровни, визуальные ассеты и экономика этим разбором не изменены.
