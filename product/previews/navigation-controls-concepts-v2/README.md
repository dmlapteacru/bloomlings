# Navigation controls and customizable Home profile

Owner correction: previous full-screen proposals did not clearly show new navigation buttons; the Home profile must support changing avatar, frame and badge.

These are enlarged concept sheets, not runtime assets or implemented screens. Built-in OpenAI ImageGen; exact prompts in `prompts.json`, original output paths in `outputs.json`.

The navigation sheet's targeted correction removes small colored empty capsule accents on inactive tiles, which looked like second buttons. Each destination remains one coherent control. Sheet annotations and heading plaques are for reviewing the concepts and are not proposed new screen content. Balance digit grouping remains governed by the existing runtime number formatter; generated text is illustrative.

- `01-navigation-buttons.png`: clear enlarged Back, Settings, Pause, Close, Speed controls and all five primary navigation destinations. Illustrated shaped faces, chunky glyphs and readable active Home state are the subjects. It does not redesign the approved connected cream secondary tabs.
- `02-profile-wallet.png`: two wallet balances and three independent frame/badge combinations using the existing Bloom portrait and cosmetic types. No fixed decorative outer arch may substitute for the user's chosen frame. Only the name ribbon is fixed decoration; portrait, chosen frame, badge/none and name are live layers. Badge placement must preserve the name and face.

Production must load actual customization from the existing profile/wardrobe services. The illustrated examples are design proposals, not replacements for the portrait/catalog files. The chosen frame is the portrait's only rim; no baked leaf frame, hard-coded avatar, mandatory badge or empty badge placeholder. All control glyphs, labels and amounts should be independent from blank material skins.
