# Bloomlings · игровой пилот v5 · L1–30

[Играть: автономный HTML](index.html). Все 30 уровней, изображения и шрифты встроены. На телефоне откройте файл в браузере с JavaScript. ☷ открывает любой уровень; ретраи свободные. После игры: ☷ → «Результаты и заметки» → «Скачать результаты .json».

## Что меняется

**Поток героев по текущему открытому фронту.** На доступную незарезервированную клетку выходит отдельный курьер. Между выходами одной капсулы 85 мс; разные капсулы работают параллельно. Нет лимита двух работников и ожидания возврата предыдущего перед новым выходом. В узком проходе выходит только один на единственную доступную цель; после очистки появляются новые назначения.

Маршрут строится при выходе по реально открытым клеткам. Заранее выбранный закрытый короткий путь не блокирует доступный обход. Квота работы закрепляется логическими правилами; физический резерв клетки создаётся при выходе. Два героя не получают одну цель. Число уменьшается при снятии клетки; место освобождается после всех обязательных возвратов, связка — после обеих команд. Счётчик 0 и готовая половина пары ещё могут занимать место.

Ручной 1×/2× и авто2× только после исчерпания исходной очереди сохранены. Они не суммируются в 4×; нет скрытого разгона от backlog. Пять мест во всей партии, скрытая глубина с L6 раскрывает верх до выбора, пары с L8, мост с L20. Обычная палитра и режим «Цвета + узоры» сохраняются.

**Восемь изменённых задач:** L5/6/7/8/9/13/17/20. L1–4 сохранены для сравнения нового потока и знакомства с материалами. На L5 контур жёлудя стал настоящей преградой; любой первый выбор остаётся исправимым. На L7 ближние зелёные листья и верх плода требуют сравнивать объём команды с доступной работой. На L9 две разноцветные связки; наL13 добавлена знакомая связка, наL17 — связка со скрытой глубиной. Для L5/7/9/13/17 сохранена доказанная полезная на вид ошибка: ход снимает клетки, оставляет игру продолжающейся, но лишает победы. На L6 проверена информационная стратегия скрытых цветов. Это не подтверждение интереса для человека — нужен новый ручной тест.

**Два новых силуэта:** L17 «Садовая лейка», L20 «Тыква у ручья». Остальные изменения рисунков ограничены контуром L5 и ближними листьями L7; общего перерисовывания набора нет. [Все 30 рисунков](art-contact.png).

**22 определения сохранены точно**, включая все шесть интересных по ручному тесту v4: L10/L15/L21/L22/L25/L29. На этих уровнях меняются поток и физическое ожидание, поля/очереди/связки/входы/мосты прежние. Для неизменённых задач воспроизведены 40 человеческих последовательностей: 22 победы и 18 поражений. Сопоставляется порядок действий и исход; старые времена не переносятся на новую модель.

## Часы и результаты

Время модели и активное время используют один источник активных интервалов. Скрытая вкладка, открытое меню и промежуток перезагрузки не начисляются попытке и не двигают героев. Переход учитывает **предыдущее** состояние активности, поэтому возвращение из паузы не добавляет весь скрытый промежуток. Подробные интервалы дробятся при событиях работы; конец попытки обрезает оставшееся время кадра.

Экспорт `bloomlings-pilot-results-5` содержит хеши каталога, правил, модели потока, часов и палитры; начальную скорость/настройки каждой попытки; pause/resume/visibility, восстановление, переключения и эффективную скорость. Исчерпание очереди отделено от изменения скорости. Ручной 2× при исчерпании очереди остаётся 2×.

- `assignments`: `[id,pod,cell,assignedMs]` — логическое назначение работы, в том числе ещё не запущенной.
- `tripPlans`: `[id,pod,cell,assignedMs,startMs,arriveMs,clearMs,returnMs,routeLength,physicalFrontier]` — маршрут и времена, зафиксированные при реальном выходе. До выхода маршрут не предсказывается.
- `workEvents`: `[modelMs,code,id]`, коды 0/1/2/3/4/5 = выход/прибытие/снятие/возврат/освобождение/назначение. В событии освобождения третий элемент — индекс капсулы; в остальных — ID курьера/назначения.
- `timeBuckets`: взаимно исключающие интервалы допустимого ввода, ожидания без ввода, хвоста после очереди и остановки. Допустимый ввод не означает полезный ход. `workActiveMs` пересекается с ними; складывать его с категориями нельзя.

Профиль рейса при 1×: 28 мс на клетку туда (минимум 180), действие 90 мс, 22 мс обратно (минимум 140), интервал выхода 85 мс. Это новый экспериментальный профиль, не секундомер Unity и не обещание определённой длительности. Не требуется довести каждую картинку до 90 с. Быстрый эталонный маршрут и последовательная отправка дают разные времена; ручной темп оцениваем отдельно.

## Проверки и воспроизведение

```bash
node tools/gameplay-pilot-v5/verify.mjs
node tools/gameplay-pilot-v5/timeline-check.mjs
node tools/gameplay-pilot-v5/clock-check.mjs
node tools/gameplay-pilot-v5/compatibility-check.mjs
python3 tools/gameplay-pilot-v5/build.py
node tools/gameplay-pilot-v5/browser-smoke.mjs
node tools/gameplay-pilot-v5/browser-check.mjs
python3 tools/gameplay-pilot-v5/contact-sheet.py
```

Нативная проверка использует фактический C# Core через `tools/gameplay-pilot-v5/check/Bloomlings.Pilot.V5.Check.csproj` и транскрипты, созданные `verify.mjs` (SDK .NET 10). [Сохранённые проверки](validation/) отделяют движок, поток, часы, браузер и архив. `generate.mjs --out=/tmp/pilot-v5-candidate` воспроизводит авторинг отдельной партии по детерминированным seed/attempt; это не команда пересборки релизных 2500.
