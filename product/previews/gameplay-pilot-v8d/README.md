# Bloomlings v8D — видно не всё

Открой `index.html` в браузере телефона. Всё встроено, сеть не нужна. Сохранение отдельное от v8C. Все уровни доступны через меню. После теста скачай JSON в «Результатах»: файл `Bloomlings-pilot-v8D-results-*.json`.

«D» — пять предложений из [разбора твоего теста v8C](../../playtests/pilot-v8c-owner-2026-10-22/README.md). Картинки, капсулы, их порядок, роли и коридоры ботов — как в v8C. Меняются только видимость очереди, капсулы «?», значки, авто-хвост и анкета.

## Что изменилось относительно v8C

1. **В очереди видно 3 ряда и край четвёртого.** Глубже не видно ничего. Так в Colony Flow: на твоей записи их L10 у края четвёртого ряда видны цвет и число (наполовину под панелью бустеров), а «?» серые и без числа. В v8D так же: край — полоска с цветом и числом, ниже пусто.
2. **«?» редкие, но важные:** только L6, L12, L19, L25 и L30, по 1–3 капсулы. Хотя бы одна — ключевого цвета: её клетки закрывают путь к другим цветам, и она одна из крупных капсул уровня. «?» прячет и цвет, и число. Капсула стоит ниже трёх полных рядов, сначала появляется серой, а раскрывается, когда становится верхней. Ключевая раскрывается в середине уровня (25–80% работы), остальные — не в самом начале и не в самом конце (15–90%).
3. **Без значков и портретов.** На капсулах, в местах ожидания и на поле только цвет и число. Значки, символы и портреты героев остались в режиме «Цвета + узоры» (выбор уровней). Кнопка ◇ внизу убрана.
4. **Авто-хвост.** Когда очередь пуста (и мостик уже выбран, если он есть), решений больше нет: муравьи выходят без интервала, все сразу, к каждой доступной клетке, а анимация идёт на ×4 (на кнопке скорости «4×»). Исход от этого не меняется.
5. **Новая анкета после уровня.** «Как ты играл?»: спланировал всю партию заранее / планировал, когда застревал / в начале подумал, потом по цветам / по цветам. И отдельно: «Нужна была капсула из глубины очереди?»: да, ждал её / хватало видимых / не думал. Вопрос про «?» остаётся на уровнях с «?».

## Честность: бот-планировщик

Раз игрок не видит всю очередь, каждый уровень должен проходиться тем, что видно. Это проверяет новый бот-планировщик (`tools/gameplay-pilot-v8d/horizon.mjs`):

- он видит то же, что игрок: 4 ряда (3 полных и край), цвет «?» не знает, пока она не наверху;
- перебирает свои следующие ходы среди видимых капсул (обычно на 4 хода вперёд) по тем же правилам, что игра;
- выбирает ход, после которого больше собрано и больше свободных мест, и никогда не ведёт к затору, если его видно заранее;
- после каждого хода смотрит заново.

Он проходит все 30 уровней, и его маршрут — сертификат уровня. Проверка также меняет местами любые две невидимые капсулы и убеждается, что бот выбирает тот же ход, то есть глубину он не подсматривает (161 проверка).

Что выяснилось по дороге:
- **L10 и L29 проходятся, только если видны 4 ряда.** С тремя рядами бот на них проигрывает, с краем четвёртого выигрывает. Поэтому край с числом важен, как в Colony Flow. L10 требует планирования на 8 ходов, остальные — на 4.
- **14 уровней из 30 не проходятся без взгляда вглубь:** бот, который видит только верхний ряд, на них проигрывает. На остальных 16 хватает верхнего ряда, планирование не нужно.
- **L15 (Hard) проходится и по одному верхнему ряду.** Это подтверждает твоё «легко»: случайные тапы на нём проигрывают (18%), но думающему игроку достаточно смотреть на верх. Кандидат на переделку в следующей версии вместе с ботом-планировщиком в коридорах ролей (предложение 6).

## Сборка и проверки

Из корня репозитория:

```sh
node tools/gameplay-pilot-v8d/fix.mjs            # content/pilot-v8d из v8C: «?», планировщик, сертификаты
node tools/gameplay-pilot-v8d/verify.mjs         # движок, авто-хвост, планировщик без подглядывания, «?», коридоры ролей
node tools/gameplay-pilot-v8d/control-check.mjs  # реальные попытки v7 на неизменённых уровнях (до авто-хвоста)
node tools/gameplay-pilot-v8d/clock-check.mjs
python3 tools/gameplay-pilot-v8d/build.py        # product/previews/gameplay-pilot-v8d/index.html
node tools/gameplay-pilot-v8d/browser-smoke.mjs
node tools/gameplay-pilot-v8d/browser-check.mjs  # 30 побед через DOM, 3 ряда + край, без значков, 4× в хвосте
node tools/gameplay-pilot-v8d/storage-check.mjs
```

Результаты — в [`validation/`](validation/README.md).
