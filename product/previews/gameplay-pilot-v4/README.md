# Bloomlings · игровой пилот v4 · L1–30

[Открыть автономный HTML](index.html). Это игровой тест, а не визуальный макет плана. Все картинки, шрифты, правила и 30 задач встроены; сеть и APK не нужны. На телефоне скачайте HTML и откройте его в браузере с JavaScript, а не в предпросмотре файлов. ZIP содержит тот же HTML. Разрешения аккаунта, отправка данных и реклама не используются.

## Что проверяем

- Цветные рисунки с L1: 16×18 → 18×20 → 20×22 → уже 24×26 на L4. Три материала с начала, четыре героя к L2, жемчуг Drop на L3, тёмная земля Twig на L4, слива Bloom на L11. Семь **точных** каналов; общий герой не делает материалы взаимозаменяемыми.
- Пять мест во всей партии. Не менее восьми самостоятельных команд; очередь не помещается в первую серию из пяти тапов. Сравнение ранних 3/4 мест осталось в отдельной v3.
- Скрытая глубина с L6, одноцветная связка с L8, смешанная с L9. Верх раскрывается **до** выбора. Содержимое фиксировано; проверена стратегия без знания скрытого цвета в двух допустимых мирах.
- Hard: L10, L15, L22, L25, L29. Для каждого доказаны две разнесённые полезные на вид ошибки, ведущие в нерешаемое состояние, включая выбор с общим материалом. Решение с максимум двумя занятыми местами невозможно. Это проверка конструкции, не обещание сложности для человека.
- Мост Sprig: один берег на L20; выбор двух берегов на L21/L22/L24/L29. В каждом двухстороннем случае замена берега меняет результат того же порядка команд. Не означает, что один берег всегда неправильный при другой подготовке. На L27 два входа вместо новой механики.
- **L15 и L22 сохраняют точные поля, капсулы, очередь, группы, входы и мост v3.** Новые палитра и рейсы применяются и к контролям. Старые пилоты, Core, клиент, 2500 уровней, магазин и экономика не изменены.

## Рейсы и управление

Курьер идёт по открытой дорожке от входа, снимает клетку своего материала и возвращается. На узком фронте работает один; при нескольких одновременных доступных клетках — до двух на команду, максимум десять на поле. Число уменьшается при снятии клетки. Место освобождается после последнего возврата; связка освобождает оба места вместе. Завершение уровня также ждёт возвратов.

Другие капсулы можно отправлять во время работы, пока есть физические свободные места. Заполненный ряд с работающими курьерами ещё не проигрыш. Готовый мост доступен и при заполненном ряду. Ручной 1×/2×; авто2× только при исчерпании исходной очереди. Скрытого ускорения нет. Меню и скрытая вкладка приостанавливают работу. Reduced motion отключает декоративное покачивание, сохраняя тот же темп рейсов.

Профиль модели в миллисекундах: выход 10/клетку (минимум 60), действие 40, возврат8/клетку (минимум 50), интервал выхода 35. У каждого рейса сохранён маршрут и зависимость от физического открытия пути. Это отдельный профиль теста, **не время нынешнего Unity-клиента**. Быстрый автоматический проход эталонным решением занимает около 18 с на L1, 26 с на L2, 57 с на L4 и 99 с на L10, с авто2× в конце и без времени на размышление. Это диагностические прогоны, не человеческие замеры и не обязательная длительность.

На капсулах всегда есть портрет, точный цвет, знак материала и счётчик. В меню уровней доступны обычная палитра и «Цвета + узоры»: второй режим меняет цвета и обязательно показывает символы на клетках. Символы можно включить и в обычной палитре. Контраст чёрного/белого текста ≥4,5:1; [диагностика палитры](../../../content/pilot-v4/palette-audit.json) не заменяет проверку на телефоне и людьми с особенностями цветового зрения.

## Как тестировать

Пройдите по порядку L1–10, затем остальные. В конце отдельно оцените сложность, интерес, узнаваемость, необходимость планирования и темп. Ретраи бесплатны; любой из 30 уровней доступен в ☷. Прогресс, незаконченные рейсы и заметки сохраняются в браузере. После теста: ☷ → «Результаты и заметки» → «Скачать результаты .json».

Экспорт `bloomlings-pilot-results-4` содержит версии/хеши каталога, правил, рейсов и палитры; принятые и отклонённые нажатия; логические и физические места; интервалы доступного выбора, ожидания работы, автохвоста и остановки; оценки и заметки. `tripPlans`: `[pod,cell,startMs,clearMs,returnMs,routeLength,worker,frontWidth]` в часах модели. `elapsedMs` — активное время попытки без меню/скрытой вкладки; оно не равно времени модели при 2×. `workActiveMs` пересекается с временными категориями; четыре `timeBuckets` взаимно исключаются. Интервалы 5+с без выбора можно найти в `intervals`, а не угадывать по одной общей длительности.

Свои результаты v4 не сравнивать как один секундомер с v2/v3 или Unity. Предыдущие ручные результаты v2 сохранены отдельно; результатов ручного теста v4 пока нет.

## Сборка и проверки

Из корня репозитория:

```bash
python3 tools/gameplay-pilot-v4/build.py
node tools/gameplay-pilot-v4/verify.mjs
node tools/gameplay-pilot-v4/timeline-check.mjs
node tools/gameplay-pilot-v4/browser-check.mjs
python3 tools/gameplay-pilot-v4/palette-audit.py
python3 tools/gameplay-pilot-v4/contact-sheet.py
```

Нативная проверка: `dotnet run --project tools/gameplay-pilot-v4/check/Bloomlings.Pilot.V4.Check.csproj -- /tmp/bloomlings-pilot-v4-verification/transcripts.json` (SDK .NET 10). В облаке пути вывода/кеша задаются явно; готовый лог лежит в `validation/native.txt`.

Генератор `node tools/gameplay-pilot-v4/generate.mjs --out=/tmp/pilot-v4-candidate` строит новую партию отдельно и пишет только найденные задачи; `complete` требует всех 30. Для воспроизведения текущей партии используются сохранённые seed/attempt в `content/pilot-v4/quality.json`. Это не команда пересборки релизных 2500.
