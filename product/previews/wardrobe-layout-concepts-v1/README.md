# Wardrobe — варианты компоновки

Исходные дизайн-концепты созданы по прежнему экрану и принятой базе Sprig. Выбран A3; ниже описана его реализация в обоих клиентах.

## Что мешало в исходном экране

Большая арка оставляет герою небольшую часть стенда. У каждого элемента каталога повторяются маленький герой, подиум, табличка и широкая деревянная полка. В трёх колонках изображение самой вещи занимает мало места.

## A — рекомендуемый

Один неглубокий каменный стенд без арки; герой занимает большую часть примерочной. Две существующие строки фильтров остаются между примерочной и каталогом. Ниже — две колонки крупных карточек вещей, приблизительно четыре видимых элемента на длинном телефоне. Толстых полок и повторных подиумов нет. Одна строка названия и компактная цена/статус встроены в карточку. Примерочная, фильтры и нижняя навигация закреплены; прокручивается только каталог.

## B — выдвижной каталог

Больше места герою, в обычном виде один крупный ряд вещей. Панель можно поднять и получить больше рядов; при этом видимая область примерочной уменьшается. Оба существующих фильтра остаются на панели. Требуется дополнительный жест и два устойчивых положения панели, поэтому A проще для постоянного выбора вещей.

## Общие правила

- Сохранить обе строки фильтров, текущие материалы кнопок и нижнюю навигацию с непрозрачной задней стенкой.
- Меняется только основной герой при примерке. Карточки показывают своё неизменное изображение вещи, независимо от надетого комплекта.
- Для Face показывать крупную оправу, для Head — убор/причёску, для Body — одежду; не повторять целого маленького героя в каждой карточке.
- На низких экранах показывать меньше рядов, сохраняя крупные карточки. Продолжение доступно обычным вертикальным свайпом.
- Названия, цены и вещи на концептах иллюстрируют компоновку; они не меняют каталог, цены или сохранения.

Файлы: `source-current.png` — реальный исходный экран; `A-fixed-two-column.png` и `B-expandable-catalogue.png` — сгенерированные визуальные концепты.

## A3 — сетка 3×3

По просьбе владельца: тот же крупный герой, стенд и фильтры, каталог из трёх колонок и трёх видимых рядов. Карточки показывают только вещи, поэтому девять вариантов можно сравнивать без маленьких героев и полок. Файл: `A3-fixed-three-column.png`. Этот концепт выбран для реализации.

Уточнение A3: кнопки покупки зелёные, валюта — настоящая иконка петалей/лотоса из игры (в кнопках и верхнем балансе). Цветок семейства Bloom остаётся только значком героя.


## Реализованный A3 и примерка

- Один крупный герой на неглубоком каменном стенде с деревянной табличкой. Арка, стрелки смены семейства, полки и мини-герои в клетках убраны.
- Обе строки фильтров сохранены. Внизу — три колонки отдельных вещей в кремово-золотых карточках; длинный телефон показывает три полных ряда, короткий — меньше рядов с тем же размером карточки.
- Герой, фильтры и меню закреплены. Прокручивается только сетка, она обрезается до фильтров и непрозрачной стенки меню. В памяти создаются только видимые строки с небольшим запасом; позиция отдельно помнится для каждого героя и категории.
- Вещи используют существующие изолированные иконки. Каталог, цены, бесплатные тестовые предметы и идентификаторы сохранений сохранены.

| Действие | На стенде | В сохранении |
| --- | --- | --- |
| Нажать непокупную/неполученную вещь | Временная примерка, надпись Preview | Ничего не меняется, петали не списываются |
| Нажать зелёный ценник | Подтверждение покупки с примеркой | Только после подтверждения: покупка и надевание |
| Отменить подтверждение | Примерка остаётся до смены вкладки/выхода | Ничего не меняется |
| Нажать купленную/бесплатную вещь | Вещь надевается | Выбор сохраняется сразу, без Choose |
| Повторно нажать надетую вещь | Остаётся надетой | Повторного списания/снятия нет |
| Нажать Default | Восстанавливается стандарт текущей категории | Сбрасывается только текущий слот; Head всегда показывает штатную причёску/шляпку |
| Сменить героя, категорию или уйти со страницы (включая Shop) | Временная примерка прекращается | Сохранённый образ остаётся |

Зелёная рамка показывает выбранную карточку; галочка — сохранённую надетую вещь. У временной примерки галочки нет. Тап по самой картинке примеряет; зелёная кнопка покупки имеет отдельную увеличенную область нажатия.

Проверки: `MetaScreenTests`, `PhoneUsabilityTests`, тесты V2-героев; интерактивные preview fixtures 26, 55, 56, 74, 75, 170 (примерка, подтверждение/отмена, покупка один раз, навигация и прокрутка).


Финальные рендеры общей реализации Android/Skia, не генерация картинок: [19.5:9](implemented/wardrobe-19.5x9.png), [16:9](implemented/wardrobe-16x9.png), [временная примерка и зелёные ценники](implemented/wardrobe-fitting-19.5x9.png). Эти файлы находятся вне игровых ресурсов и не увеличивают APK.

Дополнительно обработка отпускания пальца в Android/Skia больше не передаёт нажатие другой кнопке: свайп с меню или фильтра на ценник не открывает покупку. Unity уже захватывает исходную кнопку через EventSystem.


## Порядок предметов

Default всегда первый. Обычные вещи сгруппированы по `wardrobeClass`: причёски → панамы → кепки → береты → соломенные и характерные шляпки → короны → ночные колпаки. Затем идут сезонные/праздничные группы `wardrobeEvent`: осень → зима → Новый год. Например, зимние ушки и новогодние шапки всех героев находятся в конце Head. Body: садовая одежда → осеннее пальто → зимняя куртка. Это порядок показа; теги не вводят новые ивенты, блокировки или цены.

Класс и событие задаются явно в CosmeticCatalog.json, а не угадываются из названия или перевода. Внутри одной группы сохраняется порядок каталога; владение, цена, покупка и надевание не влияют на сортировку. Новые неизвестные классы и события остаются видимыми и группируются в конце. Существующие фильтры не меняются.
