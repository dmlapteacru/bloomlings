# Tasks: Character Art — cartoon 2D Bloomlings in play, 3D heroes on Home

**Input**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md),
[contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: The spec asks for tested readability (FR-022, SC-003), count contrast (FR-008, SC-005), reproducible art
(FR-019, SC-008) and a missing-picture fallback (FR-021). This list includes kit tests, core content tests and the art
check of `tools/artgen`.

**Organization**: Tasks are grouped by user story. Paths are from the repository root:
- `K/` means `client/Assets/Bloomlings/UI/Design/`;
- `U/` means `client/Assets/Bloomlings/`;
- `P/` means `playtest/`;
- `A/` means `tools/artgen/`;
- `C/` means `client/Assets/Bloomlings/Art/Characters/Resources/Characters/`.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task).
- **[Story]**:
  - US1: characters in the tray and the slots;
  - US2: the board of characters;
  - US3: 3D heroes on the meta screens.

## Dependencies and execution order

- **Setup (T001–T003)** → **Foundational (T004–T014)** → the stories.
- **US1** needs T004–T012 and the 2D pictures (T015–T016) before its host tasks (T017–T022).
- **US2** needs the 2D pictures (T016) and T004. It can run alongside US1's host tasks.
- **US3** needs T008–T012. Its raymarcher (T026) is independent of the 2D work.
- **Polish** runs last. T030 needs the full picture set (T016, T027).

## Parallel examples

- T017–T021 touch different files: playtest and Unity pods, slots and walkers.
- T023 (playtest) and T024 (Unity) are independent.
- T026 (3D) can be written while US1's host tasks are in progress.
- T028 (playtest) and T029 (Unity) are independent.

## Implementation strategy

1. Setup and Foundational, then **US1** (the MVP: the tray and slots with the new characters). Check the preview.
2. **US2** (the board), then **US3** (the 3D heroes).
3. Polish: originality, inventory, docs, every local check, then one push. Offer the owner an APK build (it is a manual
   workflow).
