# Implementation Plan: Character Art — cartoon 2D Bloomlings in play, 3D heroes on Home

**Branch**: `004-character-art` (work lands on `claude/great-darwin-6qrpj8`) | **Date**: 2026-10-01 |
**Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/004-character-art/spec.md`

## Summary

The new art replaces every drawn Bloomling with the art the owner approved. It applies to the Unity client and the
full playtest. The level tester is unchanged.

| Where | Look |
|---|---|
| Gameplay | 2D cartoon characters whose shape is the variant symbol, in four moods: happy, asleep, worried, blank |
| Pods and slots | the character with an "xN" count |
| Board | each target tile is a light tile tinted toward its variant, with the character on it |
| Home, splash, win and milestone, Wardrobe, profile | pre-rendered 3D heroes: four solo heroes (with blank-face versions) and the group on the stone pedestal |

The approach turns the art into files made by a tool, instead of code drawing at runtime:

- **Generator.** A new tool, `tools/artgen` (.NET 10 + SkiaSharp, the toolchain the repository already uses), does all
  the drawing:
  - the 2D characters as vector drawings ported from the approved concept;
  - the 3D heroes with a CPU signed-distance raymarcher ported from the approved WebGL concept.

  It writes 57 PNG files and a manifest into a Unity `Resources` folder. It can re-render and compare them (`check`)
  and write a review sheet.
- **Shared kit.** `CharacterArt` names the pictures and places them on pods, slots, tiles and meta screens. It also
  defines the moods, the board tile tint and the "xN" count. Both hosts read the same values.
- **Playtest.** The painter gains `Sprite`, `HasSprite` and `SpriteSkin`, and the files are embedded. Unity loads
  them from Resources into cached sprites.
- **Spec 003 cleanup.** The code-drawn kawaii figures of spec 003 FR-032 are removed. The spec 002 silhouette with
  its symbol returns as the fallback for a missing picture.

## Technical Context

**Language/Version**:
- C# latest;
- the Unity client on Unity 6.3 LTS (.NET Standard 2.1 profile);
- the playtest on .NET 10 for Android (`net10.0-android`, API 26+);
- the preview and `tools/artgen` on .NET 10.

**Primary Dependencies**:
- the existing ones: Unity uGUI, `Android.Graphics`, SkiaSharp 3.119 (preview), `Bloomlings.Core` (variant catalog);
- new: SkiaSharp 3.119 in `tools/artgen`. It is a dev-only tool and is not shipped.

**Storage**:
- 57 PNG files plus `manifest.json` in `client/Assets/Bloomlings/Art/Characters/Resources/Characters/`;
- embedded into the full playtest and the preview.

No save, content or economy change.

**Testing**:
- `tools/artgen check`: pixel tolerance, readability masks, margins, manifest;
- `client/DotnetCheck`: new `CharacterArtTests`, with the removed kawaii tests;
- core content tests: originality and the manifest;
- `playtest/preview` render checks;
- `playtest/check`;
- manual device checks.

**Target Platform**: Android and iOS phones in portrait (Unity), and the Android playtest APK.

**Project Type**: mobile game client plus a dev-only art generator.

**Performance Goals**:
- gameplay at 30 fps or more with no hitch over 100 ms on the reference low-end device (SC-006);
- pictures decoded once and cached;
- Home shows its heroes within 1 second.

**Constraints**:
- presentation only (FR-002);
- 3D pictures only on meta screens (FR-003, constitution VII v1.0.2);
- at most 6 MB added (SC-007);
- deterministic art (SC-008);
- no Colony Flow or reference-image material (FR-019).

**Scale/Scope**:
- 12 variant characters × 4 moods;
- 4 heroes × 2, plus the group;
- about 15 host files in each client;
- one new tool.

## Complexity Tracking

| Addition | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| A new tool project (`tools/artgen`) | The owner chose art that runtime shape drawing cannot produce (bezier characters, 3D renders). FR-019 needs it reproducible from the repository. | Hand-made files cannot be regenerated or reviewed as code. Runtime drawing (spec 003 FR-032) was rejected by the owner. |
| 57 committed PNG files | Both hosts need the same pixels, and Unity has no vector or raymarch renderer. | Rendering at runtime on the phone would cost seconds per hero and would differ between hosts. |
| A 3D raymarcher in C# | It reproduces the approved 3D concept without a browser or GPU, deterministically. | The WebGL concept depends on Chromium and the driver. Blender is not available. |
