# Bloomlings — четыре ракурса для Meshy / Tripo

Для каждого героя подготовлен отдельный лист из четырёх видов в T-позе на белом фоне:

| Файл | Персонаж |
|---|---|
| `sprig-four-views.png` | Sprig, исходный дизайн |
| `bloom-four-views.png` | Bloom, исходный дизайн |
| `drop-four-views.png` | Drop, исходный дизайн |
| `twig-four-views.png` | Twig, исходный дизайн |
| `bloom-alternative-four-views.png` | Дополнительный вариант Bloom с округлыми лепестками сакуры / пиона |

Порядок на каждом листе: **спереди / правый профиль** в верхнем ряду,
**левый профиль / сзади** в нижнем (см. подписи). На заднем виде лица нет.
В профиль руки T-позы направлены вдоль оси камеры
и поэтому видны в ракурсе, а не вытянуты горизонтально по изображению.

Использовать один дизайн одного персонажа за раз. Не смешивать исходную и альтернативную Bloom
при генерации одной модели. Если выбранный режим сервиса принимает отдельные ракурсы,
передавать соответствующие виды раздельно, а не загружать весь лист как фронтальную картинку.
Если доступен только один входной ракурс, лучше начать с фронтального референса.

Это сгенерированные целевые референсы, а не ортографические рендеры уже готовой сетки.
Ранее не показанные боковые и задние поверхности интерпретированы; мелкие расхождения между
видами возможны. При построении модели сверять силуэт, толщину головы/короны, расположение
лепестков и крепление асимметричного листа Twig. Листы не заменяют проверку итоговой 3D-модели.

Для первого теста: около **10 000 quads (~20 000 triangles)**, текстура **2048×2048**,
экспорт **GLB с UV и текстурами** либо FBX с отдельными текстурами. Сохранять зазор между ногами,
не сращивать руки с головой/телом. Четырёхугольники удобнее для правки деформаций; направление
рёбер на сгибах важнее самого количества полигонов. Подробнее — в соседнем
`../tpose-pack-2026-10-16/README.md`.

Исходные фронтальные референсы взяты из предыдущего T-pose pack. Все пять новых листов созданы
ImageGen 2026-10-16; точные промпты и источники перечислены в `prompts.json`, контрольные суммы —
в `manifest.json`. Альтернативная Bloom — только вариант для теста, игровые ассеты не заменены.
